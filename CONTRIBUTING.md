# Contributing

## Workflow

1. Open an issue describing the experiment, bug, or productionization task.
2. Create a focused branch from `main`.
3. Keep notebook changes reproducible.
4. Avoid committing credentials, local vector databases, or unnecessary generated outputs.
5. Describe retrieval/evaluation impact in the pull request.

## Experiments

For retrieval or prompting changes, document:
- the document/query used
- the expected behavior
- what changed
- observable quality/cost/latency tradeoffs
